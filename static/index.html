Multi-Agent Architecture

Engineered for autonomous safety.

PayGuard separates semantic understanding from financial authorization. Large Language Models never grant spending authority.

01 · INTENT AGENT Groq LLM

Intent Contract Locking

Extracts strict constraints (max budget, quantity, required features, purpose) from natural language and saves an immutable IntentContract in PostgreSQL.

02 · BUYER AGENT PostgreSQL + Groq

Inventory & Drift Intercept

Searches verified products, calculates exact base + shipping + tax formulas, and runs 5-factor drift detection with up to 3 automatic alternative search attempts.

03 · VERIFICATION AGENT 5 Compliance Checks

Independent Verification

Independently validates category alignment, purpose relevance, quantity limits, stock availability, and exact mathematical pricing before authorization.

04 · POLICY ENGINE Zero LLM

Deterministic Rule Guard

100% deterministic Python rule engine enforcing merchant max transaction caps, high-value thresholds (ASK_USER), and duplicate order blocks.

05 · PAYMENT AGENT Razorpay Test Mode

Razorpay Order & Cryptographic Signature Verification

Creates server-side Razorpay test orders only upon verified policy clearance. Never exposes secrets to frontend, and verifies authentic HMAC SHA256 payment signatures before finalizing transactions.

Zero-Trust Guardrails

Deterministic control over AI spending.

AI agents excel at discovery and formulation, but financial decisions require mathematical certainty. PayGuard guarantees that no unauthorized transaction can occur.

Intent Drift Intercept

Detects budget drift, quantity drift, category deviation, and missing specifications before orders are created.

Autonomous Spending Caps

Strict merchant transaction ceiling and high-value threshold pause transactions for human-in-the-loop approval.

HMAC SHA256 Signatures

All Razorpay payment confirmations undergo cryptographic signature verification to prevent spoofing.

Immutable Audit Trail

Every intent extraction, candidate proposal, drift detection, policy evaluation, and payment attempt is logged to PostgreSQL.
